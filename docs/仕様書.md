# お問い合わせフォーム 仕様書

## 概要
Laravelで実装した「お問い合わせフォーム」。エンドユーザーが問い合わせを送信する公開フォームと、管理者が問い合わせを管理する管理ページから構成される。管理ページはGoogleアカウントによるログインが必要で、問い合わせの検索・メール返信機能を備える。

## 技術仕様
- フレームワーク: Laravel 13 / PHP 8.3
- データベース: SQLite（`database/database.sqlite`）
- コーディング規約: PSR-12準拠（`vendor/bin/pint` で検証）
- 言語設定: `APP_LOCALE=ja`（画面表示・バリデーションメッセージは日本語）
- メール送信: Gmail SMTP経由で実送信（`MAIL_MAILER=smtp`）
- 管理者認証: Google OAuth（`laravel/socialite`）

## データベース

### `contacts` テーブル
マイグレーション: `database/migrations/2026_08_23_002606_create_contacts_table.php`

| カラム名 | 型 | 説明 |
|---|---|---|
| id | bigint (PK) | 主キー |
| name | string | お名前 |
| email | string | メールアドレス |
| subject | string | 件名 |
| body | text | 本文 |
| status | string | ステータス（デフォルト値: `新規`） |
| created_at / updated_at | timestamp | 登録・更新日時 |

### `contact_replies` テーブル
マイグレーション: `database/migrations/2026_08_23_014138_create_contact_replies_table.php`

| カラム名 | 型 | 説明 |
|---|---|---|
| id | bigint (PK) | 主キー |
| contact_id | bigint (FK) | 紐づく`contacts.id`（削除時は返信も連動削除） |
| body | text | 返信本文 |
| created_at / updated_at | timestamp | 送信日時（`created_at`をそのまま送信日時として扱う） |

### モデル
- `app/Models/Contact.php`
  - `$fillable`: `name`, `email`, `subject`, `body`, `status`
  - ステータス定数: `STATUS_NEW`（新規）/ `STATUS_IN_PROGRESS`（対応中）/ `STATUS_RESOLVED`（解決済み）
  - `Contact::statuses()`: 管理画面の選択肢（`[値 => ラベル]`）を返す静的メソッド
  - `replies()`: `HasMany`、紐づく返信履歴（`ContactReply`）
- `app/Models/ContactReply.php`
  - `$fillable`: `contact_id`, `body`
  - `contact()`: `BelongsTo`

### 管理者アカウント（`users` テーブル）
既存のLaravel標準`users`テーブルをそのまま管理者アカウントとして利用（別テーブルは作らない）。ログインはGoogle OAuthのみのため、`password`カラムは実質未使用（NOT NULL制約を満たすためfactoryのダミー値が入っているだけ）。**新しい管理者を追加するには、`users`テーブルに対象のGoogleアカウントのメールアドレスを持つレコードを事前に登録しておく必要がある**（自動登録は行わない）。

## 画面・機能仕様

### お問い合わせフォーム（エンドユーザー向け）

確認画面を挟む入力フローは**セッションベース**で実装している（hidden項目での値の再送信ではなく、確認画面表示時にバリデーション済みの内容を `session('contact.input')` に保持する方式）。

1. **入力画面**（`GET /contact` → `resources/views/contact/create.blade.php`）
   - 「お名前」「メールアドレス」「件名」「本文」を入力
   - 確認画面から「戻る」で遷移してきた場合は、セッションに保持された入力値を復元して表示
   - バリデーションエラー時は入力画面に戻り、エラー内容を一覧表示
2. **確認画面**（`POST /contact/confirm` → `resources/views/contact/confirm.blade.php`）
   - `ContactController@confirm` が `ContactRequest` でバリデーションを実行
   - 検証済みの入力内容を `session(['contact.input' => $validated])` に保存し、確認画面に表示
   - 「戻る」リンク（入力画面へ）と「送信する」ボタン（送信処理へ）を表示
3. **送信処理**（`POST /contact` → `ContactController@store`）
   - `session('contact.input')` を読み取り、`Contact::create()` でDBに保存（`status` は常に `新規`）
   - セッションから `contact.input` を削除し、完了画面へリダイレクト
   - セッションに入力内容が無い場合（直接POSTされた場合等）は入力画面へエラー付きでリダイレクト
   - 保存直後、管理者へ新着通知メールを送信（詳細は後述）
4. **完了画面**（`GET /contact/thanks` → `resources/views/contact/thanks.blade.php`）
   - 「お問い合わせありがとうございました」を表示

#### バリデーションルール（`app/Http/Requests/ContactRequest.php`）

| 項目 | ルール | エラーになる条件 |
|---|---|---|
| お名前 (name) | `required\|string\|max:255` | 未入力、または256文字以上 |
| メールアドレス (email) | `required\|email\|max:255` | 未入力、メール形式が不正、または256文字以上 |
| 件名 (subject) | `required\|string\|max:255` | 未入力、または256文字以上 |
| 本文 (body) | `required\|string\|max:2000` | 未入力、または2001文字以上 |

エラーメッセージは日本語化済み。`body` の上限文字数（2000）は要件に明記が無かったための暫定値。

#### 新着問い合わせ通知メール
- `app/Mail/NewContactNotificationMail.php`（プレーンテキスト、件名「【お問い合わせ】{件名}」）
- 送信先: `.env`の`CONTACT_ADMIN_EMAIL`で指定した固定アドレス1件（`config/contact.php`経由で参照）
- 内容: お名前・メールアドレス・件名・本文と、管理画面の詳細ページへのリンク
- **通知メールの送信に失敗しても、問い合わせ自体の保存は失敗させない**（`try/catch`で囲み、失敗時は`report()`でログ記録のみ）
- `CONTACT_ADMIN_EMAIL`が未設定の場合は送信自体を行わない

### 管理者ログイン（Google OAuth）

- ログイン手段はGoogleアカウントのみ（メール/パスワードでのログインは廃止）
- ログイン画面（`/admin/login`）の「Googleでログインする」ボタン→Google認可画面（`admin.auth.google.redirect`）→コールバック（`admin.auth.google.callback`）の順で遷移
- コールバック処理（`Admin\GoogleAuthController@callback`）:
  - Googleから返されたメールアドレスと一致する`users`テーブルのレコードを検索
  - **一致するレコードが無い場合はログインを拒否**し、「このGoogleアカウントは管理者として登録されていません。」を表示（新規アカウントの自動作成は行わない）
  - 一致すればログインし、セッションIDを再生成した上で、本来アクセスしようとしていたページ（`intended`）へリダイレクト
- ログアウト（`POST /admin/logout`）: セッション破棄・CSRFトークン再生成の上、ログイン画面へリダイレクト
- 必要な設定（`.env`）: `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI`（Google Cloud ConsoleでOAuthクライアントを発行し、リダイレクトURIとして`{APP_URL}/admin/auth/google/callback`を登録）

### 管理ページ（管理者向け、要ログイン）

1. **一覧画面**（`GET /admin/contacts` → `resources/views/admin/contacts/index.blade.php`）
   - `Contact::latest()->paginate(20)` で新着順・20件ずつページネーション表示
   - ページネーションの表示には`pagination::bootstrap-4`ビューを使用（デフォルトのTailwind用ビューはこのアプリでは未導入のTailwindクラスに依存しており、矢印アイコンのSVGにサイズ指定が効かず巨大に表示されてしまうため）。見た目は`resources/views/layouts/partials/styles.blade.php`内の`.pagination`/`.page-item`/`.page-link`で素のCSSとしてスタイリング
   - 表示項目: お名前・メールアドレス・件名・ステータス・受付日時
   - お名前をクリックすると詳細画面へ遷移
   - **検索・絞り込みフォーム**（一覧上部、GET）:
     - 氏名: 部分一致（`LIKE '%...%'`）
     - 受付日時: 開始日〜終了日の期間指定（`created_at`に対して`whereDate`で絞り込み）
     - ステータス: チェックボックスによる複数選択（新規/対応中/解決済みをAND条件外・OR的に複数選択可）
     - 各条件は独立して任意（未指定の条件は無視される）、複数条件はAND結合
     - `withQueryString()`によりページネーション時も検索条件を保持
     - 「クリア」リンクで条件なしの一覧に戻れる
2. **詳細画面**（`GET /admin/contacts/{contact}` → `resources/views/admin/contacts/show.blade.php`）
   - ルートモデルバインディングで対象の問い合わせを取得
   - お名前・メールアドレス・件名・本文・受付日時を表示
   - ステータスを `<select>`（新規／対応中／解決済み）で変更可能
   - **メール返信フォーム**（返信本文のテキストエリア＋「送信する」ボタン）
   - **送信履歴**: 過去の返信を新しい順に一覧表示（送信日時・本文）。返信が無ければ「まだ返信はありません。」と表示
3. **ステータス更新**（`PATCH /admin/contacts/{contact}/status` → `Admin\ContactController@updateStatus`）
   - `UpdateContactStatusRequest` で `status` が `新規`/`対応中`/`解決済み` のいずれかであることを検証
   - 更新後、詳細画面へリダイレクトし「ステータスを更新しました。」をフラッシュメッセージ表示

#### バリデーションルール

`app/Http/Requests/UpdateContactStatusRequest.php`

| 項目 | ルール | エラーになる条件 |
|---|---|---|
| status | `required`, `in:新規,対応中,解決済み` | 未指定、または3種類の値以外 |

`app/Http/Requests/Admin/SearchContactsRequest.php`

| 項目 | ルール | エラーになる条件 |
|---|---|---|
| name | `nullable\|string\|max:255` | 256文字以上 |
| date_from | `nullable\|date` | 日付形式が不正 |
| date_to | `nullable\|date\|after_or_equal:date_from` | 日付形式が不正、または開始日より前 |
| status | `nullable\|array` | 配列でない |
| status.* | `in:新規,対応中,解決済み` | 3種類の値以外を含む |

`app/Http/Requests/Admin/StoreContactReplyRequest.php`

| 項目 | ルール | エラーになる条件 |
|---|---|---|
| body | `required\|string\|max:2000` | 未入力、または2001文字以上 |

### メール返信機能

- `app/Http/Controllers/Admin/ContactReplyController.php@store`:
  1. `Mail::to($contact->email)->send(new ContactReplyMail($contact, $body))` でお問い合わせ者へ返信メールを**同期送信**（キューは使用しない）
  2. 送信成功後、`contact_replies`テーブルに履歴を保存（送信前に保存しない＝送信に失敗した場合は履歴を残さない）
  3. 詳細画面へ「返信を送信しました。」のフラッシュメッセージ付きでリダイレクト
- `app/Mail/ContactReplyMail.php`: プレーンテキストメール。件名は`Re: {元の件名}`

## デモ用シードデータ

`database/seeders/ContactSeeder.php` を`DatabaseSeeder`から呼び出しており、`php artisan db:seed`（または`migrate:fresh --seed`）で以下の条件を満たすお問い合わせデータを100件投入する。

- 氏名: 日本語の名字（30種）×名前（男女各20種）の組み合わせでランダム生成。偶数番目を男性名、奇数番目を女性名にすることで男女比を厳密に半々にしている
- メールアドレス: `contact001@example.com`〜`contact100@example.com`（`example.com`ドメイン、重複なし）
- 件名・本文: ショッピングサイトへの問い合わせを想定した定型文20パターンからランダムに選択（在庫・配送・返品・支払い・退会等）
- ステータス: 新規／対応中／解決済みからランダム
- 受付日時（`created_at`）: 実行時点から過去3か月の範囲でランダム（`Contact::insert()`で一括投入するため、`fillable`にない`created_at`も直接指定可能）

## 未実装・今回のスコープ外
- 添付ファイルなど、問い合わせフォームの4項目（お名前・メールアドレス・件名・本文）以外の入力欄
- メール送信のキュー化（`QUEUE_CONNECTION=database`は設定されているが、ワーカーを常駐させる運用は行っていないため同期送信のまま）
- 返信送信時のステータス自動変更（例: 返信したら自動で「対応中」にする、等）は行っていない

- 詳細画面から返信を送信し、実際にメールが届くこと、送信履歴が表示されることを確認
- `vendor/bin/pint --test` でコードスタイルを確認
- `php artisan test` でテストを実行
